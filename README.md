# Swag Labs Functional Testing

Repositório de estudos e entregas do curso **O dia a dia de um QA: a prática de testes manuais funcionais - DIO**.

O objetivo deste projeto é documentar o planejamento, os fluxos de trabalho, histórias de usuário, cenários, casos de teste e evidências de testes manuais funcionais aplicados ao site Swag Labs.

## Escopo

- **Aplicação:** Swag Labs
- **Contexto:** Loja virtual para prática de testes
- **Metodologia ágil:** Scrum
- **Gerenciamento do projeto:** JIRA
- **Documentação do projeto:** GitHub
- **Execução dos testes:** Manual
- **Nível dos testes:** Sistema e aceite
- **Tipo dos testes:** Funcional caixa-preta

## Definição de teste funcional caixa-preta

Teste funcional caixa-preta é uma abordagem em que o QA valida o comportamento do sistema com base nos requisitos, regras de negócio e expectativas do usuário, sem analisar a estrutura interna do código.

O foco está nas entradas, ações, resultados esperados e comportamentos visíveis da aplicação. No contexto deste projeto, isso significa testar funcionalidades da loja Swag Labs, como login, listagem de produtos, carrinho, checkout e finalização de compra, verificando se cada fluxo atende ao comportamento esperado.

## Metodologia, ferramentas e organização

### Scrum

O Scrum foi escolhido por ser uma metodologia ágil voltada a entregas incrementais e adaptação do trabalho ao longo do projeto.

Nesse contexto, o time trabalha com itens organizados em **Product Backlog** e **Sprint Backlog**. O Product Backlog concentra as demandas do produto, enquanto o Sprint Backlog representa os itens selecionados para uma sprint específica.

Para o QA, o Scrum é importante porque permite participar desde o refinamento dos requisitos, ajudando a identificar riscos, ambiguidades, critérios de aceite e impactos funcionais antes da etapa de testes. Assim, a qualidade deixa de ser uma atividade feita apenas no final e passa a fazer parte de todo o ciclo da sprint.

### JIRA

O JIRA foi utilizado para o gerenciamento do projeto e para a criação manual do quadro de trabalho. Ele foi escolhido porque oferece recursos importantes para times ágeis, como:

- gerenciamento de trabalho com quadros ágeis
- organização de Product Backlog e Sprint Backlog
- acompanhamento de status e transições
- obtenção de relatórios
- alta personalização
- integração com outras aplicações
- apoio à comunicação entre pessoas de produto, desenvolvimento e QA
